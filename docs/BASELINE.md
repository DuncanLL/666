本仓库从当前 R116 游戏人物 MOD 整理，只做目录归并与构建入口整理，工作台未导入。现装游戏、工作台、Steam/F 作者项目和外部光影均未因这次导入而更改。

## 实际检查

- 完整编译 31 个 Java 源文件，产出 48 个运行类。
- 与工坊基准 JAR 对比，去除编译调试属性后，48 个类全部相同，无缺少或多出类。
- `ModelAppearance` 之前由构建工具追加的可见性查询已恢复成可维护 Java 源码；仍通过完整类字节对照。
- 5 个原生库沿用原文件，逐个 SHA-256 核对。Rust/C++ 源码与当前制作源一致，本轮没有重新编译原生 DLL。
- 从仓库脚本生成完整 `Workshop/R116` 候选，1875 个文件；外部人物资源按清单读回，配置、Lua、声音声明取自仓库。
- 实际游戏的 `SteamWorkshopItem.validateContents` 通过；新 JAR 的原生初始化、11 模型资料加载、每模型 4 个物理步和释放通过；所有原生对象计数归零。
- 原生重编脚本仅检查私有工具链路径和 dry-run 命令，本轮不把它记作原生重编测试通过。
- Python 构建工具通过语法检查。私有 GitHub 仓库访问和 push 权限已读回核实。

基准身份和外部素材指纹在 `provenance/baseline.json`、`resources/manifest.json`；本机实际报告位于被忽略的 `build`，不把日志或整个成品反复提交进 Git。

## 未测与保留问题

本轮未操作游戏，没有执行工坊上传、没有安装新候选，也没有执行真实多人或订阅冷启动测试。既有切人物原生崩溃尚未确认根治。妮基塔资源保留，整备室入口隐藏。

自动审批拒绝了清理刚生成候选目录的递归删除操作。因此保留同一候选，修正打包记录后执行全量读回验证，没有另复制一份完整成品。`build` 与缓存均不进仓库。
