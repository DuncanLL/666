# 0.3.3：整备室按钮被角色预览区域遮挡

用户反馈克莱妲“闭眼”可点、“睁眼”点击无效。模型的眼睛选项和 Morph22 的0/1资料正确；错误发生在界面的输入层级。

在1100宽窗口中，角色预览面板横跨 x160–940；睁眼按钮在 x754–915，完全落在透明预览面板内。预览后创建并添加到按钮前方，只把配件内容面板重新置顶，遗漏了眼睛等其它按钮。因此点击睁眼被预览区当作拖动处理；闭眼按钮的大部分位于覆盖区外。下方部分按钮也存在同一问题。

0.3.2曾尝试调用 `backMost()`，文件已覆盖，但本机实际Java实现仅设置 `alwaysBack=true`，不重排父窗口的子控件；当时测试替身错误地执行了重排，导致该回归误报通过。用户反馈后已纠正替身，并用真实Java `UIElement.AddChild/RemoveChild/backMost/getControls` 核验这一行为。原0.3.2的“已修复”结论撤回。

0.3.3直接把原预览面板的创建/添加移到头像栏、内容面板和按钮之前，复用实际子控件顺序，去掉无效的 `backMost()` 和多余的内容面板重排。没有更改字体、控件坐标/尺寸、人物预览矩形、模型、Morph、动作、物理、JAR 或 DLL。模组元数据版本更新为0.3.3，原 Java 核心仍为0.3.1。

验证使用真实 Kahlua、实际游戏 ISButton 的鼠标按下/抬起回调、生产菜单代码和真实catalog/配件资料；基础控件及按层级命中扫描由测试替身提供，并新增真实Java控件顺序断言。纠正替身后0.3.2稳定复现 `睁眼 blocked by preview`；0.3.3修后3种窗口尺寸、4个页签共1260个采样点通过，覆盖按钮矩形、可见配件卡片、文字图像/备用文字边界，以及闭眼→睁眼、配置保存和预览拖动。已有四项胸部滑块路由/保存回归也通过。

命令：`python tools/check_chest_menu.py --hit-test`。结果在 `build/menu-check/hit-regions.json`，安装与文件回退在 `build/ui-hit-fix`。这是组件与布局回归，没有启动游戏，真实游戏鼠标操作仍待用户确认；正在运行的 Lua 不会因文件更新自动换版。
