# Native 0.2.9：NVIDIA词法兼容与芙洛伦复核

## 真实故障和最小修复

用户提供 `console (9).txt`、截图及完整报告：对方使用官方0.1.7-rc2、渲染支持0.2.7（SHA389d9bbf…）、NVIDIA RTX4070 Laptop、621.14。原人物片元02940c66034a在0(12)的`=`解析失败，13/14行报`.`/`)`，15行`normal`未定义。恰对应公共 `native_indirect.glsl` 的`vec4 packed=…`及后续引用。

0.2.8/RC3同样携带此服务，升级VP不能单独解决。0.2.9只将该GLSL局部变量及两处引用改名`gf2NativeNormalSample`，没有修改间接光算法、画面参数、材质或性能策略。

准确边界：`packed`见旧版GLSL保留字以及现代布局命名，不能笼统称现代GLSL普遍禁止。AMD和本机glslang16.6都接受旧写法，**未在本机重现NVIDIA驱动失败**；定位根据对方精确错误行和源代码对应。参考编译器通过不能代替硬件验证。规范参考：[Khronos GLSL1.40](https://www.opengl.org/registry/doc/GLSLangSpec.Full.1.40.05.pdf)、[GLSL4.60](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.html)。

构建新增自有GLSL声明检查，禁止`packed`及新旧保留名被用作局部变量；检查不以AMD或glslang是否接受为准。此项针对跨驱动词法坑，不宣称是完整GLSL编译器。

- 本机AMD真实驱动绘制无GL错误；当前13模型、48组原/早期程序（34原+14早期）、230份活动材质的编译链接和上传读回通过。它不等于13模型逐一视觉验收。

- 本机仅AMD（独显与核显），没有NVIDIA或Intel真实GPU验收。0.2.9须由对方完全重启后复测；不承诺所有驱动零错误。
