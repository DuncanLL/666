# R116 0.3.33 人物与光影单 MOD

合包使用人物 0.3.32（提交 5e84858）与 0.3.24 封装光影。工坊项目保留 3834454638，游戏内 ID 保留 AimohPmxPreview。游戏读取一个 R116 MOD 和一个 AimohPMXPreview.jar。Viewpoint 与 ZombieBuddy 沿用正常依赖，人物资源和可选角色资料包沿用既有契约。

## 启动和迁移

- R116 的人物入口先安装 Native 与 Eclipse。Viewpoint 可以在首帧前读到这两套包和封装后的数据。选择仍由玩家在 Viewpoint 操作，已选项及自定义光影保留。
- ZombieBuddy 先调用人物入口，再扫描人物补丁。合包在扫描前加载 ModelPass 类，避免其首次加载和后续重转换各接入一次人物补丁。光影对 ModelPass 的改动在已有的人物绘制准备入口首次运行时才接入。其它光影挂接提前完成，覆盖已选 Eclipse 的读取和编译。
- 若旧独立光影 AimohGF2Eclipse 和合包同时启用，重复保护停止渲染接入并保留人物入口。切换到合包时，在 MOD 列表停用旧独立光影并重启。保持原人物 MOD ID 和原有光影名称，方便旧存档和选项续用。真实旧存档的首次切换需单独验收。
- 对最终人物工坊目录做全量校验。2,218 个文件原样带入，变化仅限版本号与合包 JAR。JAR 内只在人物 Main 与 RenderPatch 的两个已核对方法末尾接入启动调用，其余人物类、原生库和渲染输入从各自基线原样打入。

## 后续构建

先准备人物发布目录和从当前光影分支生成的封装构建。以实际发布目录读回的 SHA-256 固定人物基线。

~~~powershell
python tools/package_r116_unified.py --character-project <人物Workshop/R116> --character-sha256 <人物JAR指纹> --render-project <封装光影工坊目录> --render-report <protection-report.json> --version 0.3.33 --output build/r116-single-mod-0.3.33-final/Workshop/R116
python tools/check_r116_unified.py --project build/r116-single-mod-0.3.33-final/Workshop/R116 --legacy-render <旧独立光影JAR>
~~~

- 隔离启动使用官方 ZombieBuddy 的包加载入口和官方 VP。确认首帧前两套光影可发现，封装探针哈希正确，Eclipse TAA 可展开。Native 的人物材质绑定、解绑、绘制回调各一次且顺序与原分包一致。旧独立光影先加载和后加载均触发重复保护，原有光影选择和自定义包保持。
- AMD Radeon RX 9070 XT 上通过正式合包入口安装并绘制。Native 跑过 36 帧换人物、6 次切包和 48 组人物程序链接。Eclipse 开 TAA 跑过 8 帧，探针有效，画面与分包对照一致。两套均无 OpenGL 错误。同选项下 4 份 Native 计算阶段和 66 份 Eclipse 阶段与分包展开字节一致，对应已通过的 33 组 OpenGL 参考编译链接。三个封装资源也与现装 0.3.24 逐字节一致。
- 完整工坊目录通过游戏原生校验器。本机构建和检查记录在 build/r116-single-mod-0.3.33-final 的 build.json、startup-check.json 和 component-validation.json。
- 本次现装只替换了游戏读取的独立光影 0.3.24，并备份了原文件。0.3.33 合包是独立输出，实际存档、订阅冷启动和 NVIDIA、Intel 分别验收。
