# Native 0.2.5：打开设置菜单崩溃修复

用户真实崩溃：2026-11-08 15:44:38，按 Delete 打开 VP 设置后，`AFTER_OPAQUE` 中原人物 fragment 编译失败：`PackOptions: Cannot reuse block name within the same interface: uniform`。不是以显存不足作为本次归因。

## 根因与修改

官方 VP 在菜单打开后切换到实时数字选项模式。公共接入层将分别经过宿主展开的主光、局部光和间接光服务合成同一原人物程序；每份服务都带有相同的 `PackOptions` uniform block，造成重复声明。此前直接更新 CPU 选项数组的滑块测试没有覆盖真正的静态→实时着色器重编译。

`AimohGf2OriginalProgram.singlePackOptions` 在各个最终着色阶段中保留一份相同声明，移除其余重复；若声明布局不同则明确报错，不静默选错。无该块或只有一个块的程序保持原文不变。修复位于独立公共接入层，所有角色共用，不修改 VP 原类、人物核心、源材质或光影场景。

版本升级为 0.2.5；Native shader ZIP 与 0.2.4 字节相同。人物还原强度仍为 0..1、默认 0.5、步长 0.01；保留柔和底灯及玩家当前配置。

## 验证与安装

- 0.2.4 的私有宿主复现相同重复 block 异常；0.2.5 同路径不再崩溃。
- 实际官方 0.1.7-rc2＋本机 AMD 驱动，科莱达、夏安、阿斯缇亚分别完成静态→实时→静态→实时、强度 0.5→0→1→0.5；实际像素随滑块改变，无 GL 调试错误。
- 实时模式下当前资料 46 组程序（33 源程序、13 早期程序）编译链接及材质上传读回通过。此项不等于全部角色画面验收。
- `NativePackOptionsCheck` 覆盖无块、单块、三份相同块及不同布局拒绝；普通启动、资源迁移及游戏工坊目录验证通过。
- 依据用户“已完全退出”并再次检查进程后，安装到 Steam 实际作者工坊目录、Steam 订阅缓存及本地工坊输出。只覆盖本公共 MOD 的 JAR 与 mod.info。官方 VP、人物核心、F 测试 VP/接入层、玩家配置和工坊元数据安装前后哈希相同。
- 没有启动游戏，没有上传工坊。真实游戏按 Delete 与用户验收仍待复测；NVIDIA 硬件未测。
