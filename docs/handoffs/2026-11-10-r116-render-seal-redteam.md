# R116 0.3.34 光影封装红队试读

沿用人物 0.3.32 和 0.3.24 的渲染逻辑，单 MOD 组装版本为 0.3.34。独立渲染 JAR 提供 A、B 两份同范围试读输入，方便和之前的独立渲染包对照。

## 实现

- 每次打包生成独立私有种子。四个类的名称和八个片段的值、方法名和调用顺序随构建变化。片段以短整数指令存于方法体，结合最终发布类的 SHA-256 派生密钥。先混淆现有类，再编译每包的载体和短入口，最后用进程标准输入交付密钥给构建端封装器。完整派生密钥不写入文件或 JAR。种子和对应表只保存在构建输出的 private 下。
- 运行侧沿用 JDK 的实现。正常 ZombieBuddy 挂接时登记封装加载器及载体类。被登记的类发生重转换后，后续受保护着色输入读取只返回通用加载失败。已编译并留在 GPU 上的程序在重新读源前继续使用现有程序。这项检查覆盖可观察的 Java 重转换，外部 agent 仍能在其它位置抓取源码。
- 发布端清除审核范围内的自写说明性注释，保留行位置、Iris 目标注释和第三方署名，菜单滑块声明沿用原内容。Eclipse 的自写计算输入改注释后重新生成资源指纹与清单路径。现役探针混合文件只处理已核对的自写区段。首次加载时用完的临时密钥、解包字节清零，宿主仍保留运行所需的文本缓存。
- 发行格式继续使用同一构建脚本和同一人物合包流程。正常绘制路径不执行密钥派生或检测任务。发布包内的代码和资源仍由客户端读取，盲测的结果按实际交出的完整着色文件判断。

## 本次验收

- A、B 两份 JAR 独立构建。4 个载体类名、8 个方法名与 8 段数字内容均不重合。完整派生密钥的字节、大小写 hex 及上一版固定 key 字符串未在试读 JAR 对应条目中检出。A 使用 B 的密文时在正常读取入口拒绝加载。用 A 的种子重建时 JAR 字节一致。
- 在游戏自带 Java 上用实际 ClassFileTransformer 改写已登记载体类的方法。改写后通过 Viewpoint Native 读取受保护 shader 得到通用加载失败。两份未改写的包均通过正常入口、菜单、探针资源指纹和工坊结构检查。普通构建也通过原入口。
- 0.3.34 单 MOD 通过正常 ZombieBuddy 加载和两套光影的首帧前发现。AMD RX 9070 XT 受控绘制通过 Native 36 帧与 Eclipse TAA 8 帧，OpenGL 错误为零。Eclipse 颜色和深度与 0.3.33 对照逐字节一致。移除注释和行尾空白后，4 份 Native 和 66 份 Eclipse 宿主展开的源码与对照一致。
- 状态 LIMITED_HARDWARE_VALIDATION。正式游戏、NVIDIA、Intel 和外部独立红队测试是后续验收。

本机证据在 build/r116-redteam-v3。A、B 公开试读文件在该目录的 Share 下。只将 JAR 交给试读者。用两份不同构建检验变体时，保持同一资源集合和两条计时规则。确认提取时以对方独立提交的完整着色器或 SHA-256 为准，私有输入归档可直接核对。
