# R116 0.3.44 光影封装与盲测记录

本次把 R116 的 Native 和 Eclipse 渲染输入各做了一套可独立编译和绘制的公开实现。正式游戏路径沿用 0.3.43 的渲染输入和调校。合包 MOD ID 为 `AimohPmxPreview`，工坊项目为 `3834454638`，验证宿主为 PZ 42.22.2 与 Steam Viewpoint 0.1.6.2。

## 公开实现和正式实现

- Native 的 9 份和 Eclipse 的 10 份输入各有对应的公开文件。公开着色器和清单以完整内容分发。运行时通过资源路径与公开文件的 SHA-256 选择正式输入，随后由宿主按原路径编译。合包读取加密资源时校验构建绑定，封装沿用 AES-GCM。
- 公开 Native 使用半球环境光、简化反射和独立的色阶响应。公开 Eclipse 使用基础环境光和主光，开启 TAA 时在人物合成阶段应用自己的亮度分段。公开实现保留模型、贴图和宿主接口。取消蓝紫染色后，差异主要落在阴影形状、反射和材质明暗过渡。
- Eclipse 正式路径的主光和暗部校准原由 Java 注入。0.3.44 把两段校准着色文本移出发行类的常量池，并纳入封装。正式输入才应用这两段校准。总计封装 19 份着色输入及清单，加上 2 段 Eclipse 校准。
- 封装的定位是提高静态拆包时识别正式实现的成本。正式 shader 最终会交给客户端编译器。测试正式实现是否已被定位，应核对实际运行证据、完整输出或对应指纹。

维护入口为 [`tools/basic_shader_adapter.py`](../../tools/basic_shader_adapter.py)、[`tools/protect_render_release.py`](../../tools/protect_render_release.py)、[`AimohSealedSources.java`](../../render-support/java/aimoh/gf2/bridge/AimohSealedSources.java) 和 [`SealEclipseCalibration.java`](../../tools/java/SealEclipseCalibration.java)。本次以核验过的 0.3.43 安装 JAR 为基线合包。构建种子、映射和临时明文保存在私有构建目录。

## 这轮外部盲测

本轮按移植人物渲染的任务提问，要求沿资源引用核对实际绘制。用户提供了外部 AI 的流程图和后续答复。用来对照的夏安正面单图是正式 Eclipse/Iris 离屏绘制，报告记录了 34 次人物源绘制。

1. 第一份答复找到了光影入口、JAR 接手人物绘制和公开 `composite6` 的六档色阶。它把公开色阶当成参考画面的最终合成步骤。
2. 对照图片后，它意识到参考图缺少公开实现的硬色阶。它把差异归因于人物掩码为空或参考图用了整备室着色器。实际记录指向正式 Eclipse，JAR 的早期人物绘制也会把输出绑定到 `colortex17`。
3. 再追问光照差异时，它用公开的环境光与相机补光值给出近似移植方案，并混用了 Native 的阴影阈值。这批答复没有交出正式校准源码、正式着色输入的匹配指纹或能确认实际执行路径的记录。

这次观察到的是一轮具体的误归因。外部 AI 已经能读懂公开实现，也能发现参考画面与它对不上。在留档的答复中，它仍沿着公开实现解释差异。这个结果记录为单次盲测观察，后续如有新证据可追加。
