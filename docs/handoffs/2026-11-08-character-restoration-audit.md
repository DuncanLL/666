# 人物还原审计：撤销观感预设，保留默认场景

## 用户当前目标与已撤回部分

在官方 VP 默认光影中尽量还原少前2整个人物，场景光照、天空、雾、曝光、色调、后处理不改。以用户提供的原游戏人物截图、真实原资源与实际抓帧为依据，不继续凭经验堆肤色预设。

用户已否定灯色预设及后续人物提亮/暖色去色候选：出现过曝、肤色偏移、阴影压平以及衣服/头发失真。`characterFillStyle`、`native_look.glsl`、Forward 输出调色封装已从活动源撤回；拒绝的代码、图像与工坊候选保留在被忽略的 build 目录。**禁止安装或上传这些候选。** 当前构建已与 Steam/作者工坊目录中原0.2.2 JAR逐字节相同，SHA256为 `150fa98f977a660a2d7e4b59c17bf3e2d285055327cac887243194de345bdcdc`，性能/兼容修复保留，游戏安装没有被这轮试验改变。

## 当前取得的直接证据

- 已检查的 Koleda 原材质 `_BaseColor`、`_FinalTint` 为白色；不能据观感就说是这两个参数误染。既有 Asteria 原抓帧材质参数审计无差异，15份原纹理全 mip 载荷匹配；它们不证明 Koleda 每项运行输入或所有资源已经核完。
- 原抓帧 `活动层阿斯缇亚近景2.rdc` 事件3425实际使用 `Hidden/Universal Render Pipeline/UberPost`。反汇编显示输入经过 LogC 编码，再对 t4 的 1024×32 查找表做相邻蓝色层插值。现场常量 `[1/1024,1/32,31,1]` 已读回。
- 从原 RDC 的真实绑定读出 `ResourceId::8523`：RGBA16F、262144字节、SHA256 `d0b139ece5bc71d416cf167cdbae2f22cb1ab4814649fb93011b18809d18b2ef`。不使用经验色表替代。
- 官方 VP 默认 `post.frag` 另走实际曝光、Purkinje、默认 Filimic/可选曲线、饱和度与 vibrance。当前人物直接把源材质 HDR 放进 Native HDR 后走这条链；没有接原游 UberPost 的颜色转换。两段显示处理不同是确认的缺口，但尚不能归因全部肤色偏差。
- 示例只作转换响应核对：同一HDR输入 `(0.830078,0.355469,0.292725)` 经该原表，输出线性RGB约 `(0.6803,0.3887,0.3076)`；这不是同姿态同光照的最终画面验收，也未证明该帧表适用于所有场景。

## 有边界的实施路线

1. 先关闭额外底灯，固定同一人物、材质、纹理、HDR输入及相机，拆开检查材质计算和最终显示。将当前 HDR 与原抓帧真实输入、输出逐项对齐；图像结果不合格不得用滤镜遮盖。
2. 人物依旧用已移植的原程序、原贴图与原 Pass；正常受光输入接 Native 实际场景。核原参数单位、色域、GI/直接灯与反射，而非复制某帧虚拟灯光覆盖所有场景。
3. 若相同输入对照确认需要显示适配，将原游人物颜色变换与当前实际 Native 显示链衔接。优先在独立人物接入层处理，避免重复映射；不能将原游 LUT 写到 VP 全局或把截图场景 LUT 定成万能肤色。曝光、夜间色适应和曲线可变性须明确处理，无法保证的模式明示未验证。
4. 从现有人物身份/几何与深度覆盖出发隔离人物像素；透明、描边、眼睛叠层、遮挡和运动输出要分别保护。阴影传输因子、法线及速度不能送进颜色变换。
5. 验收包括三基准角色、整个人物/身体近景、日景/室内/夜间、暗处与高光、外部遮挡。无人物的默认场景像素保持一致；纹理、UV、原色、衣服与眼睛不得被洗掉。先交付有来源的匹配对照，再由用户确认是否安装。

## 后续受控进展：轻量显示对接原型（未安装）

本节更新上节状态：已在隔离夹具实现显示对接证明，仍未接入生产安装。全部代码和原资源在被忽略的 `build/native-fill-20261108/original-audit`。

- 原资源 `PostProcessData_M` 的实际引用指向 `Hidden/Universal Render Pipeline/LutBuilderHdr`。源变体字节码与抓帧事件1245完全一致，SHA256 `3164f8a334bdb408056d00dd6d504782a9ffbccea4762df5b45cfe2d7c29ec48`，活动关键字为 `_TONEMAP_UNREAL_FILMIC`。不是凭外观选 ACES/Neutral 或自编肤色曲线。
- 从实际常量缓冲读到 FilmSlope 0.91、FilmToe 0.47、FilmShoulder 0.23、FilmBlackClip 0、FilmWhiteClip 0.035；`_HueSatCon=(0,1.234,1.001,0)`。这说明原路径不是此前试验中的统一去饱和。展示、训练和武器房的原资产配置已逐条按组件指针读回；其中曝光、对比等存在场景差异，不能按名字挑一份当通用设置。
- 使用不改原指令的 HLSLcc 转译、原常量缓冲、八张实际 R16 曲线纹理，重执行原 LUT 生成程序。生成结果与原 D3D 抓帧超过99.7%的 RGB 半精度分量完全相同，p99误差为0，最大单分量误差0.0025635，GL无错误。见 `original-lut-rebuild.json`。
- 原游戏最终输出视图为 UNormSRGB；当前独立夹具输出附件为 GL_LINEAR。分开核对了表内线性颜色和最终显示编码，不能将原线性表结果直接当PNG色值比较，更不能据此随意曝光补偿。实际游戏接收附件及 FRAMEBUFFER_SRGB 状态尚待专门验证。
- 对接原型只在已有运动/法线交接计算里追加查表，用源 MRT 已写入的法线/标记隔离实际人物覆盖，在全部人物阶段结束后处理一次颜色；原法线、速度、深度与其他像素保留。没有额外绘制、额外dispatch、新全屏图像或第二套场景渲染；GPU新增表262144字节（0.25MiB）。
- 原型将原游转换与实测默认Native显示响应衔接，静态反向表只覆盖 Filimic contrast=1、saturation=1、vibrance=.25。相机曝光单独因式分解，Native夜间适应和空气/雾/透明仍走原路径。生成反向表的CPU证明约0.10秒，发生在准备阶段，不在逐帧路径；不能把此固定条件原型当已兼容所有实时光影选项。
