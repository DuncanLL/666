# RC3 下的 Native 0.2.11 和 Eclipse 0.1.4

两个发行版均使用官方 Viewpoint 0.1.7-rc3，JAR SHA-256 为 `c032ef0655f2c97c9eb4e3f713d087a718b0a13fdac786f3e64994420aaf37e8`。原宿主文件和签名保持原包字节。两个发行版共用内部 MOD ID 与工坊项目 3834707439，分别打包。

## 已修的兼容问题

- Native 和 Eclipse 共用骨骼数据检查。标记、模型身份、旋转数据范围或 renderer 根不合规时，当前人物由宿主普通路径绘制，有效姿态到达后恢复专属效果。两条路径均通过异常标记、过短骨骼表、恢复帧的受控绘制。
- 缺失或不兼容的人物资料，以及 GPU 缺少固定绑定或纹理能力时，接入层在申请人物绘制之前停用本层效果并记录原因。Native 在同一光影下检测到人物目录注册后恢复，Eclipse 通过重新链接光影或重启重读资料。Eclipse 的 Planet Curvature 使用宿主普通人物路径，保留现有场景选项。
- Eclipse 旧顶点适配器只认历史纹理缓冲布局，芙洛伦的当前 SSBO 变体会报 `Unreviewed GF2 native vertex ABI`。两边共用缓冲适配和显式阶段位置分配，Eclipse 保留自己的缩放和 TAA。Eclipse 同时接入公共原采样器与材质缓存，沿用原 BC7、DXT1、DXT5、RGBA16F 和 mip 数据。
- Native 启动保留原有 Eclipse 文件。两条发行版的包体均继续独立，内嵌光影分别与各自基线字节相同。Eclipse 专用覆盖从仓库旧源码恢复，修改前的入口、服务与运行时类在官方 RC3 下编译所得字节与保留基线一致。

## 性能

- Native 在每个实际绘制阶段集中绑定宿主模型数据，跳过无投影候选时的 GL 状态保存，并把每部件排序深度计算合并为每帧一次。夏安受控中位数由 11.86 ms 变为 11.63 ms，最终画面逐像素一致。
- Eclipse 提交人物部件时只访问该部件的绘制批次，并复用当前配置的 TAA 抖动表、选项和材质绑定。阿斯缇亚受控中位数由 8.08 ms 变为 8.00 ms。该对照图像每通道平均绝对差小于 0.00001 个 8-bit 灰阶，未测真实游戏 FPS。

## 验证与分发

- 两版通过正常 ZombieBuddy 分派、空配置光影发现、跨目录资源契约和游戏工坊结构验证。Native 实绘阿斯缇亚、夏安、科莱达，Eclipse 另实绘芙洛伦并验证响应式 TAA。Eclipse 在角色目录缺失时仍能完成世界绘制。
- 两版分别检查当前 13 个模型资料及 48 对人物原程序，材料缓冲上传读回一致。OpenGL 参考链接通过 Native 85 项与 Eclipse 77 项，后者包括响应式 TAA 下由宿主展开的世界绘制阶段。
- 候选和按 JAR SHA 绑定的报告在本地 `build/rc3-render-stability`。两版均为 `LIMITED_HARDWARE_VALIDATION`，本机 AMD RX 9070 XT 通过，`--public` 因缺少 NVIDIA 与 Intel 实机证据而拒绝。真实存档、多人和工坊订阅冷启动另待验证。
