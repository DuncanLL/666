- `cb6f404` 对应 `0.3.22`，适配 PZ 42.22 和官方 VP RC4，沿用 Eclipse 的只写缓冲和宿主地形采样绑定修正。由实际选中的光影决定启用哪个后端。
- `1cab9a3` 对应 `0.3.23`，增加 Eclipse 的公共遮挡阶段。在场景透明物绘制前，只为原材质输出完全不透明的衣料像素写入当前场景深度。两套内嵌光影的指纹与 `0.3.22` 一致。

## 玩家反馈与验证范围

- 用户转述数位玩家反馈当前光影可用，包含 **RTX 4060 和 GTX 1060**。记录为玩家实机可用反馈。各台的驱动版本、所选后端、具体进档场景和 JAR 指纹尚无成套记录。
- `0.3.23` 的 Eclipse 受控检查在 AMD RX 9070 XT 上完成。13 个模型、38 个相关材质及新增遮挡阶段通过，共 112 组 OpenGL 参考编译链接通过。阿斯缇亚 P2 脱外套、夏安和科莱达都做了实绘。阿斯缇亚的前后遮挡对照中，后方测试物原先漏出的像素被挡住，前方测试物覆盖逐像素一致。正常 Java 启动入口、两套光影发现和工坊结构检查通过。
- 此前 RTX 4060 Laptop 玩家报告的 Native 闪烁、仅剩头脚和换人后模型消失单独记录。`0.3.22` 与 `0.3.23` 的受控换人、隐藏再显示、Native 与 VP 默认光影切换，以及人物 MOD `0.3.26`／`0.3.29` 的材质与提交对照均未复现。故障当下的绘制状态未记录，原因未定。
- 玩家反馈与正式驱动证据分开统计。`0.3.23` 的 Eclipse 发布检查仍为 `LIMITED_HARDWARE_VALIDATION`。NVIDIA 与 Intel 的逐包驱动报告、真实多人和订阅冷启动另行验收。

## 以后沿用的排查顺序

1. **先核加载条件，再查光影。** 核对游戏小版本、官方 VP 分支、JAR 指纹和 MOD 的游戏版本范围。3070 的旧日志停在 MOD 加载阶段，4070 Laptop 的旧日志则在光影已经报 `linked` 后才因人物 GLSL 报错。验收要进到实际人物绘制。
2. **用同一套规范代码覆盖各家驱动。** 对实际宿主展开的 GLSL 做阶段链接和静态检查。将 `packed` 等保留名和只写缓冲回读当成发布检查的反例。主光先在局部变量里算完再写结果，地形采样按宿主保留槽绑定。AMD 与参考编译器都可能放过另一家驱动会拒绝的写法。
3. **用前后遮挡对照验透明路径。** 只补真实不透明像素的深度，保留原材质的半透明混合。同一对象分别放在人物前后，核对后方被挡、前方仍可见，再换衣服和角色检查共用路径。对照时分开记录场景原不透明深度和当前遮挡深度。
4. **遇到间歇缺身体，按绘制阶段定位。** 先确认出事当时用的后端，再分别核对网格与材质可见性、逐帧提交、后端实绘。记录切包、换人、插帧和超分的发生顺序。玩家后来恢复可用与故障根因是否已确认分开记。

本机验证索引为 `build/combined-support/checks/validation.json`、`build/eclipse-coverage-check/coverage-results.json`、`build/eclipse-coverage-check/release-eclipse.json` 和 `build/native-flicker-diagnosis/character-native-cross-check.json`。正式验收按 [渲染发布标准](../render-release-standard.md) 记录。
