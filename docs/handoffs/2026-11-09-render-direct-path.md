# 收掉 Native 和 Eclipse 的重复绘制路径

Native 0.2.12、Eclipse 0.1.5 使用官方 Viewpoint 0.1.7-rc3，承接上一轮的兼容修正。两份工坊候选各自保留项目 3834707439。普通候选、安装和公开发布分别验证。

## 本轮简化

- Eclipse 的旧 DanRP 绘制分支在当前发行版没有可达入口。成功创建人物包时真实原程序已接管，失败时也没有可供旧分支绘制的 Bundle。移除这条分支及六处相关宿主挂接。
- 核对内嵌包的原始着色器与实际 RC3 展开源码。眼深、刘海遮罩、人物查找图和矩阵图没有采样者，移除对应分配和每帧上传。继续保留真实人物阴影和 `vpDanMotionTex`。Eclipse 用一次准备得到的部件名单做宿主过滤、深度和颜色绘制，省去旧 token 表和二次查找。
- Eclipse 的响应式 TAA 原先在检查人物标记前读取运动贴图。没有有效人物时，运动贴图是 1×1，原来的像素坐标可能越界。现在先检查人物标记与两张贴图的坐标范围，落在范围内才采样。构建验证只有 `dimensions/composite6.fsh` 的这一段源码发生变化。
- Eclipse 读取人物资源时用同一份当前光影快照校对资料身份，并对与渲染线程共享的包索引加锁，避免切包时边枚举边释放。正常帧的实时人物资料仍由现有目录提供。
- Native 每个显示帧只扫描一次已就绪的提交列表。阴影和颜色分别保留各自第一次出现的顺序，阴影视图仍走各自的候选和裁剪。去掉实际人物写入前无消费者的场景默认 SH 派发，几何诊断记录按需生成。

## 回归

- Eclipse 在 640×800 的同一人物场景里，人物辅助目标从 13,127,968 字节降到 10,436,608 字节，少 2,691,360 字节。阿斯缇亚、夏安、科莱达和芙洛伦完成受控绘制。响应式 TAA 下，两帧错误骨骼数据确实走 1×1 运动目标，有效数据返回后恢复 640×800 目标与人物绘制。缺目录时场景仍绘制。退出后五张接入资源登记表归零。
- Native 通过三基准人物、异常帧、室内夜景和双人物到一人、无人、重新入场的绘制检查，反射贴图及人物缓冲随退出释放。同设置的参考图片中，Native 的最大 8-bit 通道差为 1，Eclipse 四张对照图的最大通道差为 2。
- 受控中位数比较去掉前 12 帧。Native 夏安 11.63 ms → 10.90 ms，Eclipse 阿斯缇亚 8.00 ms → 7.56 ms。计时来自私有场景，真实游戏 FPS 待测。
- 两版均通过正常分派、资料契约、当前 13 模型和 48 组人物程序、材质缓冲读回、工坊目录检查。实际展开的 OpenGL 参考检查 Native 85 项、Eclipse 77 项通过。AMD RX 9070 XT 下受控绘制无 GL 错误，两版均为有限硬件验证。NVIDIA、Intel、真实存档和工坊订阅冷启动另待验收。候选和报告在本地 `build/render-direct-path`。
