# 整备室与活动帧实际比较

用户偏好整备室人物观感，同时明确担心展示场景布光不能直接泛化到游戏。该偏好不授权修改 VP 场景，也不授权固定搬运整备室灯组/反射。当前比较仅只读原抓帧及资源，没有改游戏安装。

## 输入与限制

本机两份新整备室抓帧及旧活动近景帧均读回完成，详细证据在被忽略的 `build/capture-comparison-20261108`。新帧是科莱达当前泳装，旧帧是阿斯缇亚；不同人物的最终肤色不能当作同一人物换场景的严格消融实验。没有要求用户重抓活动帧。

纹理调试名在全局资源目录中不完整，读取器转用实际主相机 HDR 网格 action 的状态，再只保存人物与后处理的见证。三份分别检查164、126、174个候选事件；21种实际人物 PS 变体均找到原资源中字节码匹配的元数据。未按肉眼或材质名猜常量布局。

## 已确认的共同部分

- 三份实际帧都使用 `_TONEMAP_UNREAL_FILMIC` 的原 LUT 生成变体；Slope 0.91、Toe 0.47、Shoulder 0.23、BlackClip 0、WhiteClip 0.035，`_HueSatCon=(0,1.234,1.001,0)`，白平衡约为1。
- 三份1024×32 RGBA16F色表的262144字节完全相同，SHA256 `d0b139ece5bc71d416cf167cdbae2f22cb1ab4814649fb93011b18809d18b2ef`。UberPost曝光乘数均为1。不能继续把这些帧的差别归因于整备室专用“美白LUT”。
- 其他 UberPost 程序变体存在差异：活动帧多 `_RARELY_USE_VARIENT`。已核对应局部玩家提亮参数全0，活动帧 Purkinje 为0；这不等于全部后处理逐项相同。不要把 `_Bloom_RGBM=0`误当作关闭Bloom，它是编码状态。
- 新整备室两帧中，身体11、脸13、头发12项核对到的原材质字段均与当前MOD数据一致；两帧合计72次字段核对无差异。包括白色BaseColor/FinalTint与UseRampMap/UseGIFlatten=1。
- 对实际绑定到上述三类材质的贴图，20条引用的原编码全 mip 载荷与其指定的当前catalog资源全部匹配。此数是两帧引用核对量，不是20张独立图片；不代替UV、法线/切线、全部材质和视觉验收。

## 已确认的差异

| 输入 | 两份整备室 | 旧活动帧 |
|---|---|---|
| 主光RGB | 中性白0.9/0.9/0.9 | 偏暖1.2/1.1087/0.9449 |
| 额外灯槽 | 计数4；当前前两项非零，点灯位置和颜色在两帧一致 | 计数8；含一盏约0.7的方向补光及另一组局部灯 |
| 环境SH | 明显更多蓝绿通道能量 | 相对中性的另一组系数 |
| 反射探针 | ReflectionProbe-6，256×256×6，9 mip | ReflectionProbe-5，128×128×6，8 mip |
| 反射载荷 | 两份整备室逐字节一致 | 与整备室不同 |
| SpecCube HDR首系数 | 约0.603827 | 约0.447988 |
| 主阴影变体 | `_MAIN_LIGHT_SHADOWS` | 另有 `_MAIN_LIGHT_SHADOWS_CASCADE` |

局部灯RGB不是最终贡献，仍受距离、衰减、方向与阴影影响，不能把存储值5/8直接说成皮肤亮度倍数。反射载荷一致证明这两帧共用同一图，不能单凭此断言其全部烘焙/更新策略。

## 对后续实现的约束

整备室好看确有稳定的展示场景受光、偏冷补光和场景反射条件。通用人物材质与显示算法可以复用，具体灯位、SH系数和整备室反射图不能硬塞到所有 VP 场景。

以整备室作为用户偏好的肤色、明暗和材质表现参考；活动帧作为换光照场景的补充。后续人物仍接 VP 实际场景灯光、环境与反射，在中性条件下校对参考观感，在暖灯/夜晚下允许自然受光变化。保留 VP 环境、光照和后处理；所有角色共用接入，不做逐角色美白补丁。当前没有新的游戏视觉验收或发布。
