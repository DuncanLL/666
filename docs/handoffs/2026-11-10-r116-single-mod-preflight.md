# R116 人物与光影单 MOD 合包预检

目标是沿用人物工坊项目 `3834454638` 和游戏内 MOD ID `AimohPmxPreview`。玩家订阅并启用一项 R116，通过正常 ZombieBuddy 授权后可使用人物。Native 和 Eclipse 自动安装到 Viewpoint 的光影列表，玩家自己选择。配套继续使用官方 Viewpoint `0.1.7-rc4` 和 ZombieBuddy。

正式合包以用户最终确认的人物版本为输入。当前工作为隔离预检。样本使用人物上传目录的 `0.3.26`、光影分发 `0.3.23` 和官方 VP RC4，样本的版本与指纹只用于复查这次结果。

## 已核对的接线

- 样本的两份 JAR 文件条目没有重名，合并输入也没有与官方 VP 或 ZombieBuddy 的类冲突。隔离的单 MOD 目录只包含 `AimohPmxPreview`，沿用一份 `mod.info`、`javaPkgName=aimoh.pmxpreview` 和一个 JAR。游戏的工坊结构校验通过。样本目录未复制完整人物资源。
- ZombieBuddy `2.3.4` 会先调用包的 `Main.main()`，再注册同包的人物补丁。照搬两个现有入口、从人物 `main()` 直接挂接光影，会在人物补丁注册后的重转换里把 Native 人物绘制回调插入两次。隔离测试中两套光影仍可被发现，因此仅检查菜单可选会漏过这项故障。
- 采用分步启动的原型通过。人物入口用现有托管安装器解包两套光影。在人物补丁完成注册后，通过已有 `ModelPass.prepare` 准备入口首次挂接光影。隔离 JVM 中调用两次准备入口，接入只启动一次。正常分包与延后原型的调用顺序一致，均为人物材质绑定、人物材质解绑、一次 Native 绘制回调。Viewpoint 的两个发现器都识别到已安装的光影，当前光影选择和测试自定义包保留。
- ZombieBuddy 的 `onGameInitComplete` 是一次性回调。本机有在该事件之后才从存档加载 Java MOD 的记录，正式接线需要覆盖这一入口。隔离原型验证了补丁注册完成后的调用顺序，实际首次进档及已选 Eclipse 的编译时序仍需用最终包验证。

## 旧版迁移

本机扫描的 20 份存档 MOD 清单中，12 份仍引用原独立光影 `AimohGF2Eclipse`。原型同时加载旧光影 JAR 时，重复入口校验会拒绝挂接，人物入口仍可返回。正式发布要把旧订阅与旧存档当作实际迁移场景验证。新用户走单一 R116 入口，旧用户在切换时要确保只有一个渲染接入生效，并保留 R116 人物身份、存档及玩家自己选择的光影。独立工坊项目 `3834707439` 的退役方式待正式迁移前核定。

## 人物确认后的交付检查

1. 固定最终人物 JAR、catalog、角色资源和当前光影分发的指纹。重新核对文件冲突和人物着色接口，打包保留同一个 `Workshop/R116` 工坊项目和一个 `AimohPmxPreview` MOD。既有人物资源与动作资料从最终人物候选完整带入。
2. 在干净用户目录走正常 Java MOD 授权与启动。确认只启用 R116 即可加载人物并发现 Native、Eclipse。确认启动前已选光影和玩家修改过的包得到保留。
3. 对照现用分包验证两套光影的实际人物绘制、换包和退回。确认首帧和后续帧没有重复接管。再验旧存档、仍启用独立分发器和重新订阅的路径，按 [渲染发布标准](../render-release-standard.md) 分开报告驱动和游戏验收。

本机预检记录为 `build/r116-single-mod-preflight/preflight.json` 与 `build/r116-single-mod-preflight/workshop-layout.json`。其中的 JAR 和工坊目录是用于验证启动、注册顺序与包结构的测试夹具。正式打包、安装和用户验收是下一阶段。
