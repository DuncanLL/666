# R116 0.3.5 本体运行边界修复

状态：已复现缺口并完成受控回归；真实游戏、反馈方NVIDIA及新补充的长发持续掉帧仍待确认。第三人称瞄准按用户要求暂缓，不把本轮候选写成该故障已彻底修好。

## 运行代码改动

1. **明确变形绘制的所有者。** 原Native着色适配通过`aWeights.w`识别PMX；禁用顶点数组时该值属于GL上下文，可能继承前一次绘制，不能代表模型身份。现在仅PMX提交的模型记录携带`0x1000`私有标志；Native和Iris都据此读取上一帧的局部顶点。未标记的车辆、武器与普通模型保留原算法。当前宿主模型标志最高为BAKED `0x0800`；地形顶点标志是另一套数据，不可混用。未来宿主新增模型标志时须重新核对该位。
2. **补齐Iris的形变运动信息。** 旧适配只识别Native `model.vert`，Iris `posed`路径没有读取前一次渲染顶点，独立软体形变会缺少相应速度。复用同一个源码读取入口与传输，不加绘制Pass或逐角色分支。
3. **GPU网格准备与捕获分开。** 旧会话的`ready`不代表切换资料后的新拓扑已上传；旧版可稳定复现`Mesh not ready`并被标为永久失败。现在捕获只取得已上传的具体网格；待准备状态排入已有渲染队列，完成后再发布。每份捕获命令持有自身网格，不在晚到的上传中改用另一套拓扑；旧替代网格按宿主退役机制释放。
4. **采用宿主模拟时钟。** RC2读取`Frame.simNanos`，不把渲染等待计作新的物理时间。模拟停止时旧版仍能推进物理；修后同一输入只在模拟时间推进时步进。旧宿主缺少该字段时保留原墙钟行为。60Hz策略、内部子步、最大dt与已认可的效果参数不变。
5. **补齐失败收尾与定位信息。** 模型加载后若构造缓冲区失败，释放已创建模型；重复退役不重复排队。首个GPU就绪记录列出胸部资料是否存在、物理请求、强度与错误状态。慢捕获仅限频输出分项CPU耗时及捕获间隔，不做自动重置、限帧或效果停用。

原生库、六套胸部绑定资料及其余非class JAR资源与0.3.1逐字节相同。JAR由8,249,976变为8,251,780字节，增加1,804字节；不据此推断FPS改善。人物、配件、70%空手手型、表情、语音、四滑块和材质资料均未重做。Eclipse包、渲染支持代码和分发器没有改动。

Java运行代码净增53行，包元数据统一到0.3.5；测试工具另计，不进入游戏包。没有新依赖、物理线程、物理频率设置或绘制Pass。

## 新补充的长发/蹲姿持续掉帧

用户描述：克莱妲等长发角色蹲下后疑似穿插，帧率持续恶化，站起、分开或重置后恢复。此现象尚未完整复现，不能标为修好。

分离测量作者刚体与胸部FEM：短样克莱妲的作者刚体约1ms，软体约10–14ms；这不是整游戏FPS。固定`1/60`时间步、60秒蹲姿叠加游戏原有低头动作的小样未出现持续恶化；作者刚体首尾约1.25/1.13ms，软体首尾约5.90/6.88ms。该检查不含真实绘制、GPU过度绘制、具体游玩动作图及所有穿插状态，不能据此排除用户的问题。

保留现有碰撞、求解器、频率与效果。慢帧分项记录用于在正常游玩中区分骨架/刚体、胸部软体、本体捕获与捕获之外的等待；不以可见穿模直接推定碰撞计算爆炸。

每帧不可变顶点/法线数组仍存在，没有未经测量引入跨线程缓冲池或复用同一可写数组。历史所有崩溃、车辆消失、真实多人及完整订阅冷启动仍未完整验收。
