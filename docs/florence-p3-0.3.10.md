# 0.3.10：修正芙洛伦 P3 上衣缺少绑定

用户在游戏中指出 P3 上衣整块平移、没有衣物物理。**0.3.9 的逐配件检查不足，不能把整个人物存在刚体、数值有限、能切换与静态绘制通过当作 P3 动态正确。** 本次已定位并修正模型数据，安装 F、Steam 两个本地 MOD 与两份人物工坊项目；未操作游戏、未上传。实际游戏仍待用户重启确认。

## 确切原因

源 Blend 的 `P3-衣服` 有 7,588 个顶点，但没有任何骨骼权重。MMD 导出时这些顶点全落到第 0 根“操作中心”骨骼；P3 两个材质均无动态骨骼覆盖。身体动作和裙摆物理都带不动这块衣服，只剩整体放置变换，因此出现整块平移。P1/P2/外套与头发有有效绑定，导致上轮整人检查没有暴露缺口。

另发现 `P3-足饰` 有 12 个无权重顶点。这是导入预检未拦截的源数据缺口，不是 VP 或胸部求解器缺少一个开关。

## 修正范围

- 在只读源的工作副本中，使用 Blender 官方 Data Transfer 的最近面插值，复用**同一人物** P2 衣服的已有 MMD 权重；12 个足饰点使用同一人物 P3 鞋子的权重。只对原来没有权重的顶点生效。这是重新制作缺失权重，不声称恢复了原来不存在的 P3 权重。
- 导出后共 7,600 个顶点权重改变；P3 上衣主材质 7,282 个顶点中，5,250 个接到现有动态骨骼。复用既有裙摆、胸部、颈饰等链路，没有新增骨骼、刚体或约束，没有人物／动作名称运行时特判。
- 所有顶点位置、UV、法线、三角形、骨骼名称／顺序／父链／位置逐项一致；其余网格的权重不变；252 个刚体和 309 个约束的全部参数不变。
- 模型 ID 仍为 `pmx-4818f3bdda4ec18d`，真实 PMX SHA 改为 `ba8172885eb50332c1d1f2c988eea2c9e8522990065b493e3a30ff7951e489cd`。同步 profile、controls、shading 描述、渲染 catalog 和源属性载荷中的骨索引／权重。方向、UV、颜色及几何 sidecar不改；新版胸部绑定按真实新权重重新生成。
- 人物 JAR 只更新版本提示与该模型的胸部绑定。原生库、其他人物绑定与其余运行类字节保持；没有改求解器、物理频率、VP 或渲染支持。
- 新增离线 `tools/blender_weight_check.py`，对有骨架的网格逐顶点检查真实骨骼权重。源文件在导出前能明确报出这两个缺口，修正后所有导出网格通过；不把缺权重静默交给根骨。

## 针对 P3 的连续验证

私有 Native 绘制夹具改为调用实际打包的 `PmxModel`，开启作者物理及新版胸部物理，采样 `Bob_Run.x` 并输入身体位移，连续绘制 120 帧，保存一张末帧图。记录真实物理推进 119 次；P3 顶点随动作变化，下摆与同模型关闭物理的对照出现独立动态差异，GL 错误为零。已查看末帧衣服贴合身体，不再停留在根骨位置。

该旧夹具最外层的固定说明仍写“physics off”，已在结果 JSON 保留旧说明并改正当前实际方法；`p3-dynamic-proof.json` 记录实际推进次数、胸部状态及动态对照，不以过时说明代替执行证据。这是受控运行和绘制，不是真实游戏／所有动作／所有碰撞情况验收。

完整候选通过游戏工坊目录校验与 12 模型原生加载／释放检查。安装时 Steam 作者项目的 JAR 被进程占用；已回退该处修改，保留完整候选。用户明确退出游戏后完成余下覆盖，四处均回读通过。工作台历史已替换为新指纹，避免同一路径继续指向旧标定。

面部、睫毛、眼睛及两种眼部叠层共五组原材质 buffer 与纹理绑定，逐项对照源资料一致，相关原编码纹理载荷指纹匹配；头部仍对应真实 Head_M／第 9 根骨骼。未发现串接其他角色贴图，未改脸色、光照参数或原贴图。MMD 眼影层默认 alpha=0 保持源 Blend 设置；没有原游同条件运行对照，不宣称完整视觉一致。
